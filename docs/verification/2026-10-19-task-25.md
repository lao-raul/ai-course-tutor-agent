# TASK-25 — Instructor preview verification

Date: 2026-10-19. Scope: HFR-GEN-10 only. TASK-23 / KI-001 is not closed by this work.
These are local code/test results, not a claim of hosted CI or live deployment.

## Implementation and acceptance

- AC-25.1: `previewPracticeSet` returns the immutable question draft (including its
  type-specific protected answer, rationale/rubric), revision, pinned content version,
  model/prompt/validator versions and Agent-resolved citations. Only READY generations
  in the caller's tenant are eligible; live Agent checks enforce publication and binding.
- AC-25.2: explicit instructor role AND assigned course are required. Student, teaching
  assistant and platform-admin roles are denied; cross-tenant/course/missing/unpublished
  sets fail closed. Protected preview uses `Cache-Control: no-store` and is not included
  in learner read models. Authorization is server-side, not just hidden navigation.
- AC-25.3: migration `p250001` adds `practice.preview_audits`; successful requests commit
  actor/tenant/set/version/time/correlation metadata before returning. No question text,
  answers, textbook text or learner submissions are stored in that audit. Audit failure
  returns no preview. Invalid stored questions return a generic error without logging
  Pydantic's protected input values.
- AC-25.4: instructor access discovery enables a read-only Web preview by PracticeSet ID.
  Every question is labeled AI-generated/not official. No publish/approve action exists.
- AC-25.5: unit authorization/error/audit tests, real PostgreSQL migration and audit
  persistence tests, and instructor/student browser regressions pass.

## Build, deploy and observable manual acceptance

No live rollout was performed in this task. Use the documented local deployment
script with the existing runtime secrets in the environment (do not paste secrets
into reports):

```bash
scripts/deploy-hiruzen-local.sh --host-path /Volumes/home/ChinaTextbook --tag task25-preview
kubectl --context kind-course-tutor-hiruzen -n course-tutor port-forward service/course-tutor-web 18080:80
```

The script builds images and applies Helm; the expected Practice schema is now
`p250001`. Do not reuse an old image with `--skip-build`. Follow README prerequisites
for NAS, LM Studio, Docker and runtime secrets.

Use an identity provisioned by the configured auth provider with role `instructor`,
the correct tenant and explicit `course_ids` assignment. The ordinary local student
token does not become an instructor token and must remain denied; do not elevate
the shared learner token just to test preview.

With `INSTRUCTOR_TOKEN` and `SET_ID` set privately for a READY, published set:

```bash
curl -i -H "Authorization: Bearer $INSTRUCTOR_TOKEN" http://127.0.0.1:18080/v1/practice/instructor/access
curl -i -H "Authorization: Bearer $INSTRUCTOR_TOKEN" "http://127.0.0.1:18080/v1/practice/sets/$SET_ID/preview"
```

Expect 200, `enabled: true`, protected fields, exact version/provenance and no-store.
Repeat with a student token: expect 403 without protected content. A teacher assigned
to another course/tenant must not obtain the set. In PostgreSQL inspect only audit
metadata: `SELECT actor_id, tenant_id, set_id, content_version_id, correlation_id,
created_at FROM practice.preview_audits ORDER BY created_at DESC LIMIT 5;`.

In the browser, sign in with that instructor identity, choose “教师预览”, enter the
PracticeSet ID, and check answers/evidence and the AI/not-official labels. With the
student identity the navigation must be absent and direct API requests denied.
Never attach protected preview responses or bearer tokens to public CI artifacts.
